# AR 记账服务端

Java 21 + Spring Boot 3.5.16 + PostgreSQL 17 的模块化单体。一个 Maven 工程、一个可执行 JAR、一个数据库；Flyway 在启动时迁移数据库。Flutter 使用 REST API，AR 画面渲染、相机和方向传感器在客户端完成。

## 模块

| 包 | 已实现能力 |
|---|---|
| `auth` | 邮箱密码注册、登录、7 天随机令牌、注销、用户信息、用户/管理员权限 |
| `ledger` | 创建账本、币种校验、预算保存、账本列表 |
| `bill` | 幂等记账、分页、账本/地点筛选、详情、编辑分类备注、软删除、关联退款及累计退款限额 |
| `place` | 私有地点、地图选点数据、附近地点距离与账单数，最多返回 100 个地点 |
| `media` | JPEG/PNG/MP4 私有上传、文件摘要去重、归属鉴权下载、删除、积分撤销 |
| `checkin` | 距离/时间/精度预校验、待审核打卡、审核后地域奖励 |
| `points` | 积分流水、UTC 日限额、成长等级、账单/媒体/地域积分撤销 |
| `achievement` | 首次/累计账单、城市徽章、每日记账进度（无额外积分） |
| `statistics` | 时间区间收支、分类净支出、已验证地域消费；不同币种分开统计 |
| `admin` | 打卡审核、撤销、操作审计接口；不包含管理端网页 |
| `common` | 数据访问辅助、业务错误、SHA-256 |

## 启动

安装 Docker Compose 后，在项目目录执行：

```sh
cp .env.example .env
# 编辑 .env，设置 DB_PASSWORD，不要提交 .env。
docker compose up --build -d
```

服务地址 `http://localhost:8080`，健康检查 `GET /actuator/health`。服务与数据库端口仅绑定本机；外网部署通过 HTTPS 反向代理接入，并对注册、登录和上传设置请求速率限制。PostgreSQL 与媒体均使用持久化卷，备份时需同时备份两者。

本地 Java 开发（JDK 21 或更高兼容版本、Maven 3.9+）：

```sh
# PostgreSQL 已运行时，设置 DB_URL、DB_USER、DB_PASSWORD。
export DB_URL='jdbc:postgresql://localhost:5432/note'
export DB_USER='note'
# DB_PASSWORD 从本机环境或密钥管理工具注入。
mvn spring-boot:run
```

`.env` 由 Docker Compose 读取；直接运行 Maven/Java 不会自动加载 `.env`。

打包：`mvn -DskipTests package`；运行：`java -jar target/note-server-0.1.0.jar`。

## 管理员初始化

先正常注册自己的管理账号，再由数据库运维在受控连接中执行（替换为实际账号）：

```sql
UPDATE app_user SET role = 'ADMIN' WHERE email = 'your-admin@example.com';
```

项目无默认管理账号或默认密码。管理员登录后调用 `/api/admin/**`。权限每次请求从数据库读取，不需要重新登录；不要将管理员令牌放到 Flutter 普通用户客户端。

## 积分规则（v1）

| 类型 | 单次积分 | 限制 |
|---|---:|---|
| 账单 | 10 | 每用户每天 10 笔，包括收入/支出/转账/退款 |
| 图片 | 2 | 每账单奖励 5 张，每天 20 张 |
| 视频 | 5 | 每账单奖励 2 个，每天 5 个 |
| 现场打卡 | 5 | 同一标准地点每天一次，每天最多 5 次 |
| 新地点 | 10 | 每标准地点一次，每天最多 5 个 |
| 新城市 | 100 | 每城市一次 |
| 新省级行政区 | 300 | 每省级行政区一次，无此层级则跳过 |
| 新国家/地区 | 1000 | 每国家/地区一次 |

- 所有每日限额采用服务端 UTC 日期；图片视频以上传日计，打卡奖励以审核日计。达到奖励限额仍可保存（另有存储配额）。
- 同次审核可以叠加所有首次地域奖励，用户初始所在地域也参与首次奖励。
- 新增账单和积分、媒体元数据和积分、审核和探索奖励在同一个数据库事务内完成。通过用户行锁串行化同一用户的奖励结算；唯一来源键避免重复发分。
- 删除不释放奖励次数。已撤销来源保留，重新提交相同账单/文件不会重新领奖。地域撤销后不重复发放该地域首次奖励（首版采用一次性终身奖励资格）。
- 删除账单撤销关联账单、媒体、现场奖励；地域有其他有效验证记录时保留，否则撤销。删除附件只撤销该附件奖励。
- 成长值为当前有效奖励累计值，等级为 `1 + floor(sqrt(growth / 100))`。首版没有兑换，因此可用积分与成长值相同；徽章不另发积分。
- 退款统计按退款发生日冲减支出，关联原支出分类；退款不自动撤销真实消费的记录积分。删除原账单前必须先删除有效退款。

## 位置验证边界

用户可以手工建立账单地点。创建打卡时要求采集时间在最近 10 分钟内、未来误差不超过 30 秒、定位精度不超过 100 米、距账单地点不超过 `200 米 + 精度`。这些检查不能证明真实到访，因此不会直接将客户端坐标认定为已验证。

本版使用管理员审核：管理员核对证据，并填入可信地理数据源中的标准地点、城市、省份和国家 ID。ID 区分大小写，应使用统一命名空间，例如 `osm:node:123`、`CN:440300`、`CN:44`、`CN`。城市、省份与国家层级一致性需审核员核对；服务端尚未接入地图供应商及反作弊服务。未审核时只获得账单/媒体积分。补记地点不会自动获探索奖励。

## 媒体存储边界

`MEDIA_ROOT` 指定私有目录，文件名为服务端 UUID，不使用客户端文件名。图片校验文件头及解码，限制 4000 万像素；MP4 仅检查容器头，不包含完整解码、转码、内容审核或相似视频识别。精确文件 SHA-256 在同一用户内终身去重；不检测改变编码后的相似内容。图片不自动去除 EXIF，因此不要把原文件下载接口作为公开分享接口。

单文件最大 50 MB、单账单最多 30 个有效附件、单用户累计存储 1 GiB。软删除后文件仍在私有存储中，下载权限立即失效，不释放配额。事务回滚会清除本次写入文件；进程被强制终止可能留下孤立文件，需运维定期核对清理。此版本尚无对象存储适配器及自动物理清理任务。

## 接口与范围

详见 [API 文档](docs/API.md)。请求 DTO 使用 camelCase，数据库资源响应采用 snake_case；积分汇总/认证等计算响应使用文档列出的 camelCase。分页是 `limit` / `offset`，默认 50，上限 100。

当前交付为服务端首版。下列原规划能力尚未实现，不应视为已可用：票据 OCR、视频转码、自动位置认证、后台任务重试、积分兑换与运营可配置规则、连续签到奖励、推送通知、账号注销/完整数据导出、共享账本、汇率折算、账单金额/地点修改、完整离线冲突解决。Flutter 可使用请求幂等键重试创建账单。

## API 响应格式

JSON 接口统一使用 `{code,msg,data}`，成功 code 为数字 0，失败保留字符串业务码；退出、删除和撤销返回 HTTP 200、data 为 null。注册仍为 201；文件下载仍为二进制。详见 [APP 接入文档](docs/export/APP_API接入文档.md)。
